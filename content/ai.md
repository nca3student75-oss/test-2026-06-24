# 🤖 AI 활용 제작 과정

## 활용 원칙

AI가 완성된 게임을 한 번에 제작하는 방식보다, **플레이 테스트 → 문제 확인 → 수정 방향 결정 → AI 활용 → 다시 플레이**의 반복 과정에 사용했습니다.

## GPT

- 게임 기획과 규칙 논의 정리
- 플레이 테스트에서 발견한 문제의 구조화
- 룰북·게임 소개·제작일지 등 문서 작성 보조
- 보드게임 표지용·발표용 이미지의 초기 디자인 방향 수립
- 여러 버전 사이의 변경사항 비교와 제작 기록 정리

## Codex

- 웹게임 기능 구현 및 코드 수정 보조
- 기능 추가 전 파일 구조와 충돌 가능성 검토
- 이미지가 필요한 사건·장면 구성 제안
- 기존 웹게임 규칙과 새 기능의 연결 구조 검토

## Grok

Codex에서 제안된 이미지 구성을 바탕으로 이미지 수정·보강에 주로 활용했습니다.

- 1인 플레이 전용 컷씬 제작
- 기존 캐릭터 표정 3종을 5종으로 세분화
- 기존 6인 이미지 구성에 인간 플레이어 캐릭터 추가
- 추가 캐릭터의 5가지 표정 제작
- 기존 장면을 게임 상황과 맞게 수정·확장

## 이미지 제작 흐름

**GPT에서 초기 보드게임 표지·발표 이미지 방향 설정**  
→ **Codex에서 필요한 장면과 구성 제안**  
→ **Grok에서 제안안을 바탕으로 수정·보강 이미지 제작**  
→ **웹게임에서 WebP/경량 영상으로 압축·연결**

## AI를 사용하면서 유지한 제작 원칙

- 최종 규칙과 밸런스 판단은 실제 플레이 결과를 기준으로 결정
- AI가 제안한 내용을 그대로 적용하지 않고 게임 규칙과 충돌 여부를 재검토
- 이미지 생성·편집은 제3자의 권리를 침해하지 않는 독창적 방식만 사용
- 이미지 용량과 분류 문제 때문에 후반에는 새 이미지를 무분별하게 추가하지 않고 기존 자산을 재사용
- 웹게임은 오프라인 보드게임의 규칙 검증 도구라는 역할을 유지하면서 스토리 기능을 확장

## 보고서에서 강조할 수 있는 점

이 프로젝트에서 AI는 단일 도구가 전체 결과물을 대신한 것이 아니라, **기획·구조화·코드·이미지·문서화 단계에 서로 다른 방식으로 사용된 제작 보조 도구**입니다.

특히 실제 오프라인 플레이에서 나온 피드백이 기능 변경의 출발점이 된 경우가 많았고, AI는 그 피드백을 빠르게 실험 가능한 형태로 구현하고 정리하는 데 활용되었습니다.

## 추가로 연결할 자료

- 전체 제작일지
- 전체 상세 버전 로그
- 게임 소개 및 플레이 방법
- AI 프롬프트·활용 예시 문서
- 이미지 제작 과정 비교 자료
